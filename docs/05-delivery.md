# 产品、成本与实施计划

## 1. 首版边界

首版包括论坛提案导入与创建核对、提案详情、投票、改票/撤回、实时预览、公开证据和复算，以及公开只读 API、Atom/RSS 订阅。讨论留在 Nervos Talk；发起与执行遵循已确认的 DAO 流程。工具可以显示里程碑及支付链接，但不默认实现另一套社交平台、DID 注册、任务系统或金库自动化。

本轮采用可读票面与流程细化，核心仍是完整签名选票由中继发布到链上。期限型授权（默认一年即 365 链日、最长 365 链日）、第二个在线钱包的连接与签票、到期续期及安全撤销进入首版。网页生成本机 key 为可选候选，不是首版必做项。自动延期、可配置利息/年龄/乐观投票等不进入首版代码或隐藏开关。面向非技术评审的逐步说明见 [完整用户流程](10-user-journey.md)。

用户免费是首版硬约束：合资格用户的授权、续期、投票、改票、撤回与恢复不支付链费，不承担载体容量，不要求准备普通 CKB。中继/运营方及备用帮助者承担这些成本；C 自付研究模板不算已支持的免费钱包路径。

本文件中的工期和服务目标是工程估算/验收建议，不是已经测得的性能或预算报价。

## 2. 用户流程

### 2.1 浏览器钱包

```text
打开论坛中的正式投票链接
  → 查看固定提案、预算、接收方、规则及截止说明
  → 连接钱包，读取可支持的存款主体
  → 看到预计票权和不计入的存款原因
  → 选择赞成/反对
  → 钱包核对标题、预算、收款地址与选择，签署“仅本次投票”的消息
  → 收到回执：中继已收到 → 已广播 → 链已收录 → 达到确认要求
```

余额页面不只显示一个总数字。它分辨 active deposit、withdrawing、未支持 lock、索引未同步和链分歧。用户不能把“服务暂时查不到”误认为“没有投票资格”。

### 2.2 Neuron 用户

首版提供“一次设置、期限内多次投票”。首次连接第二个已验收的在线钱包，以它保管的 key 作为投票 key；按 Neuron 存款地址列出本金和 deposit 笔数，设置期限（默认一年即 365 链日，可选 30/90 天），用各 owner 在 Neuron 签 GRANT，并由中继代付发布。相同地址多笔存款不逐笔授权；不同 HD 地址分别授权。一条地址不能自动发现整本 Neuron 钱包的其他地址。

在线钱包自己保管私钥，投票站不接收私钥、助记词或钱包恢复秘密；不把 Neuron 助记词导入第二个钱包，也不用转移 DAO 存款或给投票 key 充值。建议在在线钱包里为投票单独建立一个账户，不使用日常交易账户：任何连接过的网站都能请求该账户签名，而 GRANT 会公开这个地址代表哪些存款（[11 §4.2](11-authorization.md)）。下一次投票，连接同一在线钱包，核对提案和选择，网页为每个已授权 owner 准备独立代理 ballot，由钱包确认并签名。界面可以合并引导，实际钱包弹窗次数按验收公布。连接钱包或保持登录态不能代替具体选票签名。

A 地址两笔 10 万和 20 万、B 地址一笔 30 万：首次两份 GRANT，以后每个提案两张由 key 签的票，无需再打开 Neuron。有效票权仍逐 owner/DAO outpoint 计算。只提交了 A 时不能提前显示 B 已完成。

不选择授权、授权失效或希望直接接管某提案时，仍可走 owner 直签：复制可读票面 → Neuron 选择该存款地址签名 → 粘贴 → 本地验签 → 中继发布。owner 直签对该提案优先，后续代理票不能覆盖；该提案再改票仍用 owner，其他提案正常使用授权。Neuron 指定地址签名见 [源码](https://github.com/nervosnetwork/neuron/blob/a926e3383d3a3e305b3bde7d233474515ef01a2e/packages/neuron-wallet/src/services/sign-message.ts)。

管理页显示每个地址的 key、到期时间、授权锚点、链上状态与恢复进度。续期/换 key 由 owner 签一份新的控制消息，锚点更新者生效；自然到期保留已经有效投出的票。丢失/被盗时：已准备好新 key 的，每个地址签一份“换新 key 并撤回旧 key 未结束投票”的 GRANT，一步完成；暂不换 key 的，签“停止授权并撤回未结束提案的代理票”。单独撤销后再换 key，须等撤销确认生效才生成新 GRANT。高级“仅停止新投票”明确说明保留旧票。不能把删除本地地址清单、清浏览器缓存或网页登出当成撤销。

硬件钱包验收既包含投票，也包含 GRANT 的目标 key 和期限、REVOKE 的影响范围。研究固定版本的 Ledger Nervos app 只显示消息前 61 字节，换行与非 ASCII 字符显示为 `*`；因此每种签名文本的首行都是 ASCII 摘要：选票为选项、提案编号与预算，GRANT 为目标地址缩写与到期日，REVOKE 为撤销模式，其余字段仍全部签入。这是有限的显示保证：设备上看不到 owner、网络、标题、收款地址、policy 和锚点，这些依赖电脑端核对全文；16 位编号与地址缩写只是辅助标识。当前 app 与固件的实际显示必须真机复核。未通过的组合标明不支持，不能要求裸哈希盲签。[Ledger 研究固定版本](https://raw.githubusercontent.com/obsidiansystems/ledger-app-nervos/6da88ee51e53542daf07ef5a9677733fcbea5782/src/apdu_sign.c)

协议字段和恢复边界见 [11](11-authorization.md)。

### 2.3 改票与撤回

页面显示当前 **已收录** 的选择、authority、授权版本与选票锚点，而不只显示本地刚点的选项。改票即签一张锚点更新的新票；提交尚未确认时允许重发相同 envelope，也可以把最新一张单独交给其他中继，不需要先发布已放弃的中间版本。撤回是独立按钮，说明其不计入 quorum。同一地址两次改票之间要等出新块（约 8–10 秒），页面在此期间置灰改票按钮。两个设备在同一个块内签出不同选择时，提示“存在冲突，需要重新确认一次”，再签一张新票；换 key 使用新授权序列，代理票不能阻挡 owner 接管。签名前检查节点同步，收录后核对新票确已成为当前选择（[11 §5–6](11-authorization.md)）。

### 2.4 后台失败

用户看到“中继已接收，尚未写入公开记录”，并可下载选票、切换中继、让帮助者代付发布。临近截止清楚提示需给上链留时间，不把“点按钮的时间”承诺为计票时间。所有帮助文案来自固定协议，运营者不临时解释迟到票。

切换中继优先重发完全相同的 envelope，不要求改票或重新签名；只有用户改变选择、修复冲突或原文确有错误时才重新签署。任意帮助者可支付 B 的承载费用，不必是存款地址本人；用户只有 DAO 存款、没有零钱时仍可使用这种代发。免费中继与帮助者均不可用时，界面诚实显示服务不可用和待发布状态，不要求用户充值或付费；运营验收必须覆盖备用赞助路径，不能声称任何故障下都绝对能赶上截止。在线钱包在镜像重新连接同一 key 的能力须实测；不能调用旧 key 时提供 owner 重新授权等已验收路径。若开放本机密钥或通用 passkey 候选，还须验收相应备份/域名恢复；不能以“可自托管”推断旧密钥自动跨站可用。

### 2.5 提案人和协调者

1. 提案人粘贴 Nervos Talk 链接，工具读出 category、修订版本、正文、创建时间、可取得的点赞数和收款地址，显示证据来源。
2. 按现行规则生成类型、时长、整体预算的 quorum 和通过条件，不允许自由填写为零或用首付款代替整体预算。美元计价等特殊条款固定汇率依据及 CKB 基数，留给既有流程核对。
3. 自动检查无法证明的事项（例如历史时间窗口内点赞数）明确标为需人工核对；协调者按现有职责记录核对意见，不创建新的选民准入名单。
4. 提案人核对完整标题、钱包用短标题、预算、收款方与规则，用每个发起者存款地址签 `omavote-proposal-v2` 文本（首行显示提案编号与预算），并证明发起门槛；默认由中继发布，提案人可自行发布同一份已签材料。
5. manifest 须比开票块至少早 `opening_confirmations` 个块收录，协调者须在开票前发布准入记录（[03 §3、§3.1](03-protocol.md)），之后正式目录与论坛建立交叉链接。发布失败时仍为待发布，不启动一场只存在后台的正式投票。
6. 投票中原帖发生变化，显示版本差异和警示；已冻结提案不随之修改。争议标记记录理由、证据、签名与处置，不删除选票或改写票数。

论坛回帖先提供可复制的链接和结果文本；机器人自动回帖作为可选运维集成，需配置论坛授权，失败不阻断投票或复算。通知优先采用公开 feed 和页面提醒，不要求邮箱、Discord 或 Telegram 账号，不收集与选票绑定的订阅身份。

## 3. 主要界面

| 页面 | 默认显示 | 展开的高级信息 |
|---|---|---|
| 提案列表 | 正式/测试标识、名称、预算、状态、截止 | poll_id、规则版本、来源 |
| 提案创建与核对 | 论坛证据、标题、预算、收款方、待人工核对项 | manifest 原文、签名、准入证据与发布状态 |
| 投票页 | 提案编号 `#`（与钱包首行一致）、正文摘要、全文入口、YES/NO、个人预计权重、总进度 | 存款排除原因、接收 script、签名原文 |
| 我的地址与回执 | 当前连接钱包、逐地址授权 key/到期、当前选择、代理票提醒、续期与 owner 恢复、中继状态 | 授权锚点与 ID、ballot_id、链位置、原文下载；本机候选的可选备份入口 |
| 结果页 | YES/NO、quorum、阈值、预览/已复核状态 | 逐票表、逐 outpoint 明细、证据包、独立 verifier 指令 |

不要在普通投票流程里要求用户理解 SMT、witness index 或 indexer。需要用户判断的内容则不能藏起来：签了什么、是否动本金、是否付费、会公开什么、何时才算投票成功。

显示“参与地址数/投票主体数”，不显示未经证明的“独立人数”。临时预计票权与最终权重明确分开，尤其是投票期间提款或新增存款时。

投票者列表展示地址、预计/最终权重、选择及更新历史；提案人已声明且已证明控制的地址可单列，避免暗示已识别所有关联方。昵称或论坛身份如有可选展示，不产生权重、优先级或“更可信”的排名。进度曲线展示已收录票和相应链状态下的估算，不混入未发布队列作为正式票数。

结果页分别展示“按规则计算的结果”“数据/验证完整性”“治理复核与执行状态”。两份结果不一致时提供逐票和逐 outpoint 差异入口；部分统计不得出现正式通过的绿色状态，也不得生成可直接触发付款的动作。

## 4. 钱包/脚本支持矩阵

支持状态应按“钱包版本 × 网络 × 完整 lock 模式 × 签名方式”发布。

| 资产控制方式 | 首版目标 | 验证重点 |
|---|---|---|
| Neuron 软件单签、标准 secp lock | 必须优先覆盖 | 消息格式、指定 HD 地址、多 deposit、复制粘贴 |
| 在线钱包保管的投票 key | Neuron 用户首版主路径；首个 PoC 目标为 MetaMask 类 EVM EOA，JoyID 须先定义独立 adapter ID | 手机连接、全文显示、多地址签票体验与弹窗次数；key descriptor/控制证明、地址显示与 GRANT 首行一致、签名弹窗显示请求来源、独立投票账户引导、重连/账户切换/恢复；无需 CKB |
| 本机专用 secp 投票 key | 可选候选，非首版必做 | 加密保管/可选备份、浏览器存储留存、跨站恢复、XSS 与撤销 |
| 浏览器 CKB 单签钱包 | 优先 | CCC 或原生签名返回格式与真实 owner 关联 |
| 通用 passkey 投票 key | 独立 PoC 后决定 | RP ID/origin、UV、备份/同步、域名故障与 owner 恢复 |
| EVM EOA 控制的普通 Omnilock | 优先 | auth flag、网络参数、完整 args、personal_sign |
| 历史 Portal Wallet / PW Lock | 尽量首版覆盖 | 不要求迁移老存款；不能凭 EVM 地址自动猜所有脚本 |
| JoyID | 独立 PoC 后决定 | 主/子密钥、WebAuthn、授权状态、消息或交易路径 |
| Ledger 经 Neuron | 独立真机门槛 | 屏幕可读性、长消息、路径、当前 app/固件版本 |
| 多签、特殊 Omnilock flags | 后续明确支持 | 全阈值、时间/管理员等授权语义 |
| 未知/可升级自定义 lock | 不自动兼容 | 需可审计 adapter；不能只验交易成功 |
| 池化、托管、iCKB/dCKB 等 | 另行政策与技术研究 | 谁能代表底层本金、避免映射资产双计 |

此前补充研究的主网存款统计（见 [01 §8](01-research.md)，原稿已删除）作为钱包优先级与迁移测试的参考输入。其记录约 95% deposit 本金使用标准 secp 单签 lock；这不证明同样比例的用户使用 Neuron、冷钱包或已参与治理，也不证明本产品已覆盖这些本金。本轮没有独立重跑该统计。

上线前应在固定区块 hash 上重跑可复现普查，同时按本金和主体数报告支持范围，并对照实际历史参与者的钱包需求。保存数据来源、分页范围、tip/hash 和脚本版本；实时分页期间链变化必须处理。若某类老用户被实质排除，不能以“以后再支持”宣称无损替换。JoyID 主密钥优先做 PoC，子密钥与未知 lock 不因能发交易就自动支持。

## 5. 工程拆分

优先使用 TypeScript + CCC 构建静态前端与 Node.js 服务；SQLite 可满足首版单实例索引与队列，按公开数据增长情况再迁移 PostgreSQL。独立参考 verifier 可采用 Rust，避免同一实现错误在前后端相互验证。研究模型中的 Python 不是生产实现建议。

```text
packages/protocol       规范 schema、编码、域分离、纯计票规则
packages/auth           逐版本 lock/message adapters
packages/web            静态前端，钱包交互、回执与导出
packages/service        CKB 历史扫描、可重建索引、只读 API
packages/relay          envelope 队列、预算、代付与回执
verifier                独立读取节点和原始证据的实现
fixtures                正负签名向量、真实脱敏交易、重组案例
```

这是建议的后续代码结构，当前仓库仅有设计与模型。

部署可把 service 和 relay 放在一个进程/容器，但权限与代码模块分离：索引只读链；代付热钱包只保存有限周转 CKB；金库密钥不进入同一环境。提供静态包、版本 hash、可固定镜像 digest 的部署文件和从零恢复指令。

数据库保存 blocks/hash/parent、DAO outpoints 与花费位置、完整控制历史/当前 grant/撤回屏障、ballot appearances、有效性、receipt 和待发队列。最终金额不能经过 JS `Number` 或 SQL 浮点；API 返回十进制字符串。所有链派生表可重建，数据库里的 materialized tally 是缓存；待发队列、回执和中继私钥不承诺从链恢复。客户端投票私钥也不属于公开恢复输入。

首次全量重放可能是最大成本。先测吞吐、磁盘与恢复时间，再决定 checkpoint 频率。公共预建快照加速模式须显示其信任来源；严谨模式仍能从自己的已验证历史构建。不要为了上线快而删除独立模式。

历史索引与 tip 差分可作为加速候选：自有验证节点的完整 DAO 索引回放，以及固定 tip 后回滚到截止状态，都要与基准扫描产生同一集合 hash。实现固定分页视图、节点/indexer 同步检查和重组重试；不能把公共 API 返回的列表当作完备性证明。API 与 feed 使用同一可重建缓存，规范见 [协议 §12](03-protocol.md)。

## 6. 手续费与周转容量

| 成本 | 谁承担 | 能否回收 |
|---|---|---|
| 钱包消息签名 | 用户操作成本 | 无链上费用 |
| envelope 批量上链的交易费 | 中继/运营方/帮助者，用户支付 0 | 不能回收 |
| carrier 普通 cell 容量 | 中继/帮助者，用户不占用自有资金 | 花费 carrier 后可回收剩余本金 |
| 历史节点、数据镜像、API | 运营方/独立观察者 | 属运维成本 |
| 首次扫描、复算、备份 | 运营方/审计者 | 属算力和存储成本 |

费用应以 `serialized bytes × fee_rate` 的单位关系估算，并由构造后的完整交易与节点策略校验。举例：如果某笔交易计费大小恰为 20,000 bytes、费率为 1,000 shannon/1,000 bytes，则其按字节计算的费为 20,000 shannon，即 0.0002 CKB。**这是算术例子，不是当前网络报价**；实际批次包含额外 input、output、witness，需检查 cycles、最小费率和网络接受情况。

运营界面分别显示网络费与可回收周转容量，不能把 139 CKB 容量当成烧掉的投票费。投票用户界面显示“用户费用 0，由中继承担”；用户不需要先充值、支付手续费或锁定周转 cell。官方中继不可用时提供备用赞助者，不能把自付交易作为普通用户完成投票的必经步骤。

赞助策略对赞成、反对、撤回一视同仁；不向选民发奖励资产，不按权重发返利。其是否落入现有禁止投票空投规则的解释，应在切换提案里说明，不由开发者暗自认定。

## 7. 体验门槛

建议至少邀请 8–12 名不同背景的真实用户，覆盖软件 Neuron、多地址 Neuron、硬件、浏览器钱包与移动设备。在测试网/明确无治理效力的演练中记录：

* 已有钱包的浏览器用户，理想路径一次可读签名；操作完成时间目标不超过 30–60 秒，不含出块确认。
* Neuron 首次授权单地址：连接在线钱包、复制授权文本、Neuron 签名、粘贴和上链；操作目标 2–3 分钟以内，不含建立新钱包和链上确认。再次投票按在线钱包连接/签名确认路径计时；续期、换钱包与撤销另测。
* 免费路径：投票 key 与 owner 的普通余额均为零、仅 owner 持有 DAO 存款时，授权、投票、改票和恢复仍由赞助者支付；关闭官方中继后能切换免费帮助者。C 若要求用户自付费用或容量，不算已通过钱包支持验收。
* 多地址用户分别测试 1、3、10 个地址，同地址多笔存款另测；记录首次授权、下次投票、不同到期日、部分地址恢复、改票与中断恢复的耗时及漏掉的金额，不能被平均数掩盖。
* 钱包实际签名界面能核对标题、预算、收款方和选择；网页解释不能替代设备上的显示。中英文标题、超长文本和不支持字符均有明确拒绝/修正流程。Ledger 用户仅凭首行摘要能说出自己签的是哪个提案、什么选项，或授权给哪个地址、到哪天。
* 默认中继目标 60 秒内发出交易；链收录/确认时间单独报告分位数，不将其包装为固定 SLA。
* 任何人都能说清“签完”“中继收到”“链上收录”和“最终计入”之间的区别。
* 默认 API 关闭后，已有回执不丢失，参与者能完成切换或代发；独立审计者能复算。

若目标无法达到，先调整钱包交互、批量引导和中继策略，不强制迁移本金。首版在线钱包须完成 key adapter、实际签名显示与 owner 恢复验收；不能只比较点击次数。若另行开放本机密钥候选，必须完成其存储、安全与恢复审查，不能以它替代未验收的钱包路径。

默认一年（365 链日）、最长 365 天是已选产品要求。验收需覆盖自然到期保留旧票、安全撤回所有未结束代理票、owner 接管、授权冲突、更换 key、零余额 key 与零余额恢复消息。浏览器内“验证”分别标注自身收录检查、给定数据包验算和完整历史复算，不能只显示一个无范围的绿色结论。参与人数与票权变化受议题影响，不作为工程保证。

## 8. 实施阶段与交付门槛

原 8–12 周是加入完整授权前的两人工期粗估。v0.3 增加密钥保管、历史授权、恢复与第二实现覆盖，必须在 P0 重新拆分和估算，不能把旧数字直接当作当前完整范围承诺。

可读编码器、期限型授权、在线钱包 key adapter 与连接/签票、提案创建、多地址恢复与只读 feed/API 均纳入 P1/P2；第二套 verifier 必须实现同一授权语义。本机密钥库是可选候选，另列实现和审查范围，不作为首版交付依赖。下表时间保留为旧阶段粗估参照，各阶段需按新增范围重新估算，不是当前总排期。若选 marker 脚本或新增交易 adapter，另列实现、部署和审计工作量；自动论坛机器人不作为首版切换依赖。

| 阶段 | 建议时间 | 具体产物 | 继续的条件 |
|---|---|---|---|
| P0 规则与证据冻结 | 约 1 周 | 兼容矩阵、precision/phase-1/时钟/阈值决议草案、历史样本 | 每个未定义边界有明确候选，不伪装成默认共识 |
| P1 技术 PoC | 1–2 周 | 授权与选票状态机的可执行实现和测试、机器 schema、可读票面与授权控制跨语言/真机向量、在线钱包 key adapter/显示/重连与 owner 恢复验证、carrier 与可选 marker 对比、固定历史余额与重组实验 | 满足下文 V2 冻结条件；不消费 DAO 本金；钱包可核对所签内容；完整 script 验权正确 |
| P2 最小产品 | 2–3 周 | 提案创建核对、在线钱包连接/签票、授权/续期/安全撤销、多地址引导与恢复、静态投票页、中继、索引、公开 API/feed、导出、回执、CLI | 从创建到独立复算完整跑通；切换中继无需重新签票 |
| P3 安全与用户演练 | 2–3 周 | 第二 verifier、攻击 fixture、8–12 人 UX、全站断电演练 | 两实现一致；无 blocker；独立出口实际可用 |
| P4 影子运行与切换 | 2–3 周 | 影子投票比较、规则确认、运维与恢复手册 | 每个差异都可解释，切换经授权 |

**可以先做与需要等待的部分。** 原始区块读取与 DAO 历史回放不依赖授权和选票语义，现在即可开始。中继排队规则、授权状态机和最终线格式，须等 [09 §10](09-design-update.md) 的修订经测试验证后再固定。

**V2 冻结条件**（在 P1 内完成，缺一不可）：

1. 授权与选票状态机的可执行实现，覆盖 [11 §8](11-authorization.md) 全部场景及评审反例：收窄格式清单、换中继发布最新改票、被扣留的早签票、同一块内的两张不同票、取低于最新块的锚点、节点落后时的恢复、撤销与新 GRANT 乱序、GRANT+CANCEL、锚点被重组移除，以及流程记录的原样重发、扣留后首次发布与过期。
2. 乱序收录与重组的组合测试，以及性质测试，例如“收窄格式清单不复活授权”“最新改票不依赖中间版本发布”“撤销一经生效，不会被锚点更早的记录推翻”。
3. 机器可读 schema、跨语言编码向量和真实签名向量。
4. 首版钱包 PoC：Neuron（含 Ledger 首行显示）与 MetaMask 类 EVM EOA（含手机连接、全文显示和多地址签票）。

P1 若发现消息授权对核心钱包不现实，应及时改变通道选择，不在一个未验证假设上堆完整产品。P3 若签名/资产关联失败，不以“只差一点 UX”上线。仅有计算模型通过不足以跨越这些门槛。

## 9. 迁移

1. **历史归档**：导出可获取的 Metaforo 提案、结果、绑定数据和委员会说明，保留原来源与取得时间；不足之处标记。不能伪造缺失的用户签名，也不把后补数据标作当时上链证据。
2. **只读对照**：对历史投票复算可还原的部分。比较原始展示、公开纠正结果和新规则候选。结束快照与逐次请求余额可能本来不同，差异不自动意味着谁算错。
3. **影子投票**：新工具明确显示“无治理效力”。原平台在此期间仍是唯一正式入口，不把两边票数相加。
4. **正式切换**：冻结新规则 profile、支持矩阵、数据存证策略和官方入口，公告何时起新 poll 有效；所有进行中的老 poll 按原流程结束。
5. **停机准备**：两家可独立运行的中继、可下载静态包、镜像数据、完整 verifier 和既有资金执行者的复核流程都就绪。

用户已明确换工具属于元规则事项，由用户与既有治理流程推动；软件不裁决批准程序的合法性，只提供影子投票、正式状态区分和证据。任何规则澄清仍按既有程序完成。不能因为技术评审同意某架构，就认为社区已批准时点、精度或投票准入变化。

此前补充研究中的 Metaforo 历史样本（摘要见 [01 §8](01-research.md)，原稿已删除）可作为归档与影子运行线索；P0 须从 Metaforo 原始数据和委员会纠正说明重新采集核对；旧绑定关系最多可供用户导入地址清单，不能导入为新工具的投票授权。重复绑定、历史累计存款、quorum 填零、存款变化后权重不更新、正文或收款方变化，均纳入迁移解释和回归场景。

## 10. 开源与维护

建议生产代码采用 MIT 或 Apache-2.0 中的一种并统一说明，依赖遵守各自许可；原始协议、测试向量和构建方式公开。当前设计稿不代替项目正式许可决策。

版本不可变，旧 verifier 可下载；安全修复公布影响哪些 poll，不能自动覆盖旧规则。依赖更新和域名部署有明确 review；发布包与源码 commit 可对应。每次正式投票结束生成可离线保存的完整证据包并由至少两处独立镜像留存。

运维日常关注：索引落后高度、链分歧、中继积压、热钱包周转余额、失败签名分布、缺失 witness、审计结果差异和临近截止的未收录票。监控告警不能自动改变资格或投票期限。

## 11. 上线前真正需要决定的事项

| 决策 | 本设计建议 |
|---|---|
| 架构基线（已选） | 按用户本轮选择以 B 推进；A 保留作需重新决策的备选，C 按钱包增加，D 独立评估 |
| 签名票面（已选） | 可读文本与规范 body hash 共同绑定，按协议确定性重建，不再直接签 JSON |
| carrier（默认已选） | 普通 cell + 完整 witness；marker 只在 P1 证明收益并完成独立审查后考虑 |
| 最终票权时点 | 统一截止状态；明确相对于历史实现的差异 |
| phase-1 与利息 | 只计 active deposit 原始 capacity，不加利息 |
| 小数和 67% 边界 | 先核对/确认，再固定 profile；不能默认称完全兼容 |
| 时间窗口 | 可复算的链时间方案，公开与严格 UTC 的差别 |
| 钱包最低覆盖 | 保留 Neuron 与主流已存在存款路径；由脚本分布及实测决定 |
| 谁付链费（已选硬约束） | 用户免费；中继/运营方/帮助者支付链费与容量，公开预算及公平限流，免费恢复和故障旁路纳入验收 |
| 是否自动付款 | 首版保留现有执行流程，不自动付款 |
| 期限型投票密钥（已选） | 首版支持，默认一年（365 链日）、上限 365 链日；Neuron 首次授权在线钱包，之后用它签票，包含续期与安全恢复；本机密钥可选，按 11 分别验收 |
| 永久授权、代表制、私密投票、身份系统 | 不进入首版；需要时另行设计与评审 |
| 流程签名角色（已选方向） | 委员会/协调者使用独立流程密钥与明确阈值；格式见 [03 §3.1](03-protocol.md)。成员名单与阈值沿用既有治理确定的结果，初始配置写入切换元规则提案并作为部署参数固定，之后由委员会阈值签 ROLES_UPDATE；验证报告注明初始 `roles_hash` |
| Neuron 批量签名/连接（已选方向） | 并行评估，不作为 Omavote 首版交付依赖 |
| 切换与规则澄清（已选方向） | 支持用户打包为公开元规则提案，各项差异逐项披露，系统不替治理批准 |
| 尾盘只收直接票 | 首版不启用：rules_profile 预留 `delegate_cutoff_ms` 并取 0；以后启用须经规则确认。见 09 §6 |
| 首个在线钱包 | MetaMask 类 EVM EOA（`evm-personal-message-v1`）做首个 PoC，重点验证手机连接、全文显示和多地址签票；最终支持范围以 PoC 为准。JoyID 须先定义独立 adapter ID |
| 开票确认块数 | `opening_confirmations` 以 100 作测试候选，随规则 profile 确认；manifest 与准入记录适用同一要求，100 不代表已证明安全 |

这些是下一步团队和治理流程的决策清单，不是本次调研尚未完成的占位。技术上的可行路径、安全边界和验证方法已经分别给出；不能替社区宣布尚未确认的规则生效。
