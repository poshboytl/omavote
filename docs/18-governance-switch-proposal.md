# 投票工具切换与规则澄清提案（草案）

状态：供既有治理流程审议，**尚未提交、签署或批准**。本文是 M7 切换提案的准备材料，不产生官方准入、角色任命或生效时间。正式发布前，由提案人补齐 §3 的附件与决定；开发链的公开密钥不能代替治理成员。

## 1. 目的与边界

**提议内容**：用 Omavote V2 替换现有投票入口。
- 签名与上链：选民只签用途明确的可读消息，消息原文上链；
- 免费发布：中继或自愿帮助者免费发布；
- 计票：从 Nervos DAO 历史本金计票；
- 复核：结果任何人都能用自己的节点复算。

**选民不需要做的事**：不向新合约转移本金，不交出助记词。网络费与载体周转容量由中继承担。

**资金执行**：仍由既有委员会按治理程序人工审核和支付。软件不持有金库密钥，不自动拨款。

**影子期**：
- 现有平台仍是唯一正式入口，两个平台的票数不相加，影子结果不能作为付款依据；
- 切换时进行中的旧投票按原流程结束；
- 只有公布生效边界之后新登记、并获正式准入的提案，才适用新规则。

## 2. 请求确认的规则

下表是当前软件规则集（`omavote-ckb-community-fund-v2`，见 `GET /api/network` 的 `default_rules`）的具体行为。每项都要确认它与历史治理规则一致，或明确批准其变化。不能只批准“换一个网页”就默认全部同意。

| 项目 | 当前候选 |
|---|---|
| 票权资产 | Nervos DAO type、data 为 8 个零字节的存款（phase-1 开始后不再计入）；完整 lock 即 owner；按原始 capacity 计本金，不含利息 |
| 最终快照 | 截止前最后一个被接受区块的状态；截止后的存取款不影响已冻结的结果 |
| 金额与门槛 | 以 shannon 精确整数计算，不逐票截断。quorum：grant 为预算 ×3，meta_rule 为 185,000,000 CKB。通过率：YES/(YES+NO) 分别至少 51% 和 67%，含边界。CANCEL 不计入两边，也不计入 quorum |
| 发起资格 | 所有发起人对同一 manifest 签名；去重后各 owner 的有效本金合计至少 100,000 CKB；预算、收款人完整 lock、正文与讨论证据、规则在登记时冻结 |
| 时间 | 使用 CKB 链时钟：截至父块的 37 个时间戳取中位数。投票期 7 个链日，可能与墙钟 UTC 不同。manifest 与准入记录须至少早于开票 100 块收录（`opening_confirmations`，候选值） |
| 授权与改票 | 授权逐个完整 owner 签发，期限最长 365 个链日；锚点最新的有效票决定当前选择，同一锚点的不同票互相冲突；owner 直接投票后，该提案不会自动交回代理 |
| 撤销与恢复 | 自然到期与 STOP_ONLY 保留此前的有效票；带 STOP_AND_CANCEL_OPEN 的 GRANT 或 REVOKE 撤回未结束的旧代理票；不会回退到更早的代理票，也不追溯已结束的结果 |
| 发布期限 | 授权控制最长 1 个链日；流程记录候选 72 小时（`process_publication_delay_ms`） |
| 公开证据 | 完整消息与签名进入链历史；任何人都可以免费代发合法消息。“给定证据包的复算”与“自有节点的完整历史复算”所证明的范围不同，分别说明 |
| 免费赞助 | YES、NO、CANCEL 一视同仁；不给选民奖励，不按票权返利。请既有治理明确它与禁止投票空投规则的关系 |
| 治理流程 | 协调者负责准入（ADMISSION）；委员会负责治理状态（GOVERNANCE_STATUS，如暂停执行）、结果确认（RESULT_ATTESTATION）与执行记录（EXECUTION），见 [03 §3.1](03-protocol.md)。它们与数学结果分开：冲突、暂停与复核都不修改 `result_core`；执行记录不能代替对付款事实的核验 |

## 3. 正式发布前必须补齐的附件

1. **网络与规则**：
   - 网络 genesis 与脚本注册表；
   - 实测通过的钱包与 lock 支持矩阵（[17 §2](17-external-acceptance.md)）。未经实测的复杂 lock 不宣称支持；
   - rules、policy、registry 的精确 JSON 与哈希；
   - `opening_confirmations`、结果确认数与复核窗口的正式取值。
2. **初始流程角色**：
   - 完整的 `process_roles` JSON；
   - 每位成员的公开密钥描述；
   - 协调者与委员会的阈值、排序后的成员 key ID；
   - 最终的 `initial_roles_hash`。

   阈值沿用经认可的治理决定。服务端固定这个哈希，不接受“最先发布者”自封的角色。之后的更换由当前委员会按阈值签 `ROLES_UPDATE`。
3. **软件与审计**：
   - 源码 commit、不可变发布包的 SHA-256（[15 §2](15-operations.md)）；
   - 两套验证器的版本，另一作者的实现或独立审计结论；
   - [17](17-external-acceptance.md) 中真机、真人、规模与运营的证据。
4. **运营安排**：至少两家独立运营的免费中继，分别给出：
   - 域名与 TLS、回执公钥；
   - 赞助预算、限流与恢复策略、值守安排；
   - 故障切换与备份恢复的演练报告。

   不要求用户在故障时自行充值。
5. **影子对照报告**：每个样本列出：
   - 旧平台的来源与取得时间、原结果与公开的纠正说明；
   - V2 冻结的 manifest、截止快照与全部差异。

   缺少历史签名或原始证据的部分标为不可复原；旧的绑定清单不能导入为新授权（[05 §9](05-delivery.md)）。
6. **治理决定**：
   - 既有流程的提案、讨论与批准公告链接，以及决定人；
   - 生效日期与对应的规范区块边界；
   - 官方目录与论坛的交叉链接；
   - 进行中旧投票的清单及其归档责任人。

附件不全时继续影子运行，不设正式切换时间。普通选民不需要接受开发者代填的成员、阈值或公钥。

## 4. 影子运行与差异处置

**样本选择**：选取覆盖以下情形的历史与影子样本：
- 重复绑定；
- 同一 owner 多笔存款、余额变化与提款；
- quorum 错填、小数与 67% 边界；
- 正文或收款人修订；
- 免费中继中断。

**比较原则**：逐条比较可还原的旧规则结果与 V2 候选结果。不能把预期之内的快照差异称为旧平台错误，也不能把缺失的历史补签成当时的证据。

**进入审议的条件**：每次影子投票结束后，由非中继运营方用自己的已验证节点复算（`omavote verify`、`verify-evidence --rpc` 与另一套验证器），完整的 `result_core` 与 `result_hash` 都相同，才进入审议材料。

**阻止切换的情形**：
- 未解释的分歧；
- 钱包签名显示不足；
- 免费恢复失败。

修复后重新列明版本与影响，保留之前的报告。

## 5. 生效与维护

**生效步骤**：
1. 经既有治理批准后，运营者按批准文件固定配置：`initial_roles_hash`、网络与规则、`process_publication_delay_ms`、上线边界 H0；
2. 发布审议附件与不可变软件包，公告生效边界；
3. 之后才为该部署设置 `governance_confirmed = true`。

这个布尔值只控制软件中的标签，不能证明合法性。每个新提案仍需协调者准入。

**维护要求**：
- 旧版验证器、源码以及每次正式投票的完整证据包，至少保存在两个地方；
- 依赖、签名适配器或规则的变更都要公开评审，不能静默改写旧票或旧结果；
- 发生链分歧、结果冲突、漏洞或数据不完整时：暂停资金执行，公告受影响的提案，按已授权的程序处理。软件不会自动延期、删票或重新付款。

批准记录、生效边界、角色附件与运营负责人目前都未确定。本草案已备好供审议，不能据其存在宣称 M7 切换已完成。
