# 新版完整用户流程

这是基于 v0.3 设计的产品走查，不是已经上线的操作手册。签名与计票以 [协议](03-protocol.md) 为准；钱包支持以实际验收矩阵为准。文中的金额是示例，最终规则边界仍须确认。

## 1. 用户会用到什么

日常入口是一个手机和电脑都能打开的浏览器网站。在线钱包按已验证的连接方式使用；Neuron 用户首次授权、续期或恢复时另开 Neuron 签消息，授权期内连接第二个在线钱包日常投票。没有额外投票账号、DID 注册或迁移存款步骤。用户的授权与投票均由中继免费发布，不要求在线钱包有 CKB。

后台中继代付链费、发布完整选票，索引服务提供快速查询。审计者使用独立验证器和自己的 CKB 节点；普通投票者不需要安装节点或命令行工具。金库仍由现有多签成员人工付款。

```mermaid
flowchart LR
    A[论坛讨论与正式提案] --> B[浏览器核对内容]
    B --> C[钱包签可读选票]
    C --> D[中继代付并发布完整选票]
    D --> E[链上收录与确认]
    E --> F[截止结算与独立复核]
    F --> G[现有金库多签人工执行]
```

## 2. 提案人先做什么

1. **在论坛完成讨论。** 继续使用 Nervos Talk 和现有讨论规则。
2. **在投票站粘贴帖子链接。** 页面读取标题、正文、修订版本、发布时间、可取得的点赞数和收款地址。
3. **核对预算和参数。** 工具根据类型和已确认规则生成 quorum、通过率和时长，不让提案人自由填一个有利门槛。分期付款仍按整体申请预算核对 quorum；特殊币价条款列清来源与时间。
4. **补齐人工核对。** 网站只能看到当前点赞数时，不把它说成“一周内点赞”的证明。协调者按现有职责核对并留存材料。
5. **签署并发布提案。** 提案人确认完整标题、钱包中显示的短标题、预算、收款方、规则和时间，用每个发起者存款地址签署提案文本；文本首行显示提案编号与预算。默认中继发布；提案人也可发布同一份已签材料。材料不足或尚未发布时，页面不会显示已经正式开票。
6. **发布正式链接。** 提案须比开票时间至少早规定的区块数上链，协调者在开票前用流程密钥发布准入记录；满足后，在论坛和官方提案目录提供同一投票链接与提案编号。论坛自动回帖可选；没有机器人时复制即可。

之后修改预算、收款方或其他实质内容，需要重新创建提案，不能暗中改正在投票的内容。

## 3. 一名 Neuron 用户怎样投票

假设小林有三笔存款：A 地址两笔共 30 万 CKB，B 地址一笔 30 万。

### 3.1 首次设置

1. 从论坛正式链接进入浏览器投票站，先阅读提案与规则。选择 Neuron，填入持有存款的 A、B；页面列出两行地址和三笔存款。一个地址查不到时显示查询失败，不冒充零权重；网站不能凭 A 自动发现整个 Neuron 钱包。
2. 连接一个已支持的在线钱包。页面建议在钱包里为投票单独建立一个账户，不用日常交易账户：任何连接过的网站都能请求这个账户签名，而授权会公开它代表哪些存款。它将保管日常投票 key，网站通过对应 adapter 取得并核验密钥标识，不取得私钥或助记词。不把 Neuron 助记词导入这个钱包；原 DAO 存款不用转过去，在线钱包无需充值 CKB。具体可用钱包以验收清单为准。
3. 选择期限，默认一年（365 链日），可选 30 天、90 天。页面说明 A、B 授权给当前连接钱包的哪把 key、此授权不能动存款资金、预计到期时间与恢复方法。
4. 复制 A 的授权文本，在 Neuron 选择 A 签 GRANT，粘回；再对 B 做一次。共两份授权，不是按三笔 deposit 签三次。文本首行写明目标钱包地址的缩写和到期日，小林把它与在线钱包里显示的地址对照；全文绑定目标 key、期限、链上锚点和发布期限，不能只签一个随机登录码。
5. 中继代付发布两份授权。等到页面分别显示已收录/确认后，才用它们签新票；没有存款迁移交易。签完未上链的 GRANT 还不能代表 owner 投票。

### 3.2 每次投票

打开提案，连接首次获授权的在线钱包；已有连接可以继续使用。页面列出它可代表的 A、B 和预计权重。核对预算、收款方、选择与将代表的地址，点“投票”，在在线钱包中确认并签名，不用再打开 Neuron。钱包为 A、B 分别签署明确的本提案选票，网页可以合并引导；实际弹窗次数以适配验收为准，不承诺多个地址只弹一次。

连接钱包相当于进入自己的投票界面，不能代替签票。每次投票或改票都要签明具体提案、owner 和选择，服务器不能仅凭登录态替小林投票。

中继把完整签名票发布上链。页面逐地址显示：

| 状态 | 实际含义 |
|---|---|
| 已签名 | 还在设备，尚无发布证据 |
| 中继已收到 | 有回执，尚未上链 |
| 已广播 | 已送网络，不保证已被收录 |
| 链已收录 | 可定位完整原票，尚需规定确认 |
| 达到确认要求 | 当前链视图达到确认条件；最终权重仍按截止状态计算 |

A 已收录、B 待发布时，只显示 A 的已收录预计票权；不得先宣布 60 万全都完成。key 自己不需要 CKB，正常消息路径也不需要 A/B 有用于手续费的普通 cell。

每张代理票收录后，A、B 的公开 feed 和页面都会提示“已由投票 key 代投”。如果小林没有投过这一票，说明 key 可能被诱导签名，小林可以用 Neuron 直接投票覆盖，或安全撤销授权。

### 3.3 续期、直接投票与丢失恢复

到期前提示续期；小林用 A、B 在 Neuron 分别签一份新的 GRANT（锚定在更新的区块，自动取代旧授权），可以保留原 key 或换 key。自然到期不撤掉已经有效投出的票；新投票要有当时有效的授权。仅换 key 不自动改变旧选择，新 key 需对提案重新投票。

不想授权，或要直接接管某提案时：复制本提案票面 → Neuron 选择 owner 签名 → 粘回 → 中继发布。直接票优先；该提案以后再改票仍用 owner，代理不能重新覆盖。其他提案继续使用授权。

清除投票站缓存或换设备时，重新连接保管同一 key 的在线钱包即可找回公开授权；仅丢失网站缓存不等于丢失钱包私钥。钱包本身的恢复按其机制操作，投票站不接收钱包恢复秘密。若改用不同 key，仍需用 Neuron 重新授权，不能靠网站账号找回替换授权。

钱包 key 丢失或怀疑被盗时：已准备好新钱包的，点击“换新 key 并撤回旧票”，每个地址在 Neuron 签一份授权，一步完成换 key 与撤回；暂不换 key 的，点击“停止授权并撤回未结束提案的代理票”签 REVOKE，以后要授权新 key 时，页面等撤销确认生效后才生成新授权。页面逐地址列已生效与待发布，直到所有需要恢复的地址完成。签名前页面会检查所连节点是否已同步，落后时先提示；撤销上链后核对确已生效，才显示“已撤销”。不影响 owner 直接票，不追溯已截止提案；高级“仅停止新投票”明确告知旧票保留。续期、撤销和重新授权也由中继免费发布。

在线钱包在镜像站能否重新连接和使用同一 key，须按其实际接口验收；通用 passkey 尤其不能推断能跨域调用。不能沿用原 key 时，提供 owner 重新授权等已验收恢复路径，不虚报自动切换。授权算法和限制见 [11](11-authorization.md)。

## 4. 浏览器钱包和其他钱包

已支持的浏览器钱包可以直接连接并签可读消息，不需要手工复制粘贴。仍需逐完整 lock 验证归属；一把密钥可能对应多个 script，不因显示相同身份就自动累加所有地址。

钱包若自己持有符合规则的 Nervos DAO 存款，可以直接用自己的 owner 身份投票；替 Neuron 地址投票时，则依赖这些地址的有效授权。两种情况都分别验证和计权，不因“连接了钱包”就产生额外票权。

网页生成本机密钥是不想使用第二个钱包时的可选候选，须独立完成保管、备份、浏览器存储与恶意脚本风险验收后才提供。它不是默认流程，也不是首版必做项。完全不授权的用户仍可每次用 Neuron 签直接票，中继免费发布。

JoyID 主密钥、Ledger 等按真实钱包测试决定支持状态；不预先承诺所有固件或子密钥均可用。多签或无合适消息签名的钱包，如果其交易 adapter 已验收，可使用 C：构造同 lock 的普通资金自转账，由所需成员签名，包含选票承诺。当前自付模板需要普通可花费资金和额外操作，不消费 DAO 存款，但不满足用户免费要求，因此仅为研究候选。只有费用和周转容量由赞助者承担的安全模板验收后，才开放为产品钱包入口。尚未验收的 lock 明示不支持，不把“交易能成功”冒充“能够安全投票”。

## 5. 投票期间怎样看进度

投票页显示当前已收录选择、当前链状态下的预计票权、通过比例和 quorum 进度；地址列表可查看更新历史。地址数不标为独立人数，后台收到但未上链的票单独列为待发布。

同地址新增存款，在推荐截止快照模式下会扩大最终有效本金，无需仅因增加存款重签；换到新地址则需要该地址自己的有效选票。启动提款会减少仍处于 deposit 状态的本金。截止时冻结最终状态，之后取款不会追溯改结果。

用户可订阅公开 feed，收到开票、临近截止、结果或争议更新。通知只是提醒，不能保证最后一秒提交一定赶上链收录。页面说明链时钟与实际钟表时间可能偏离。

## 6. 改票、撤回和冲突

| 遇到的情况 | 页面和协议怎样处理 |
|---|---|
| 原先赞成，现在反对 | 签一张新票，锚定在更新的区块；旧票公开保留但被覆盖 |
| 不想参与 | 签一张新的 CANCEL；及时收录后不计入双方和 quorum |
| 多地址只改了其中一个 | 只修改已签并及时收录的那个地址，不自动替其他地址改票 |
| 手机和电脑先后签了不同选择 | 锚点更新的那张生效；若两张在同一个块内签出，显示冲突、暂不计该地址，引导再签一张明确选择 |
| 十秒内想连续改两次 | 页面要求等出新块（约 8–10 秒）再签，避免同一块内的两张票互相冲突 |
| 第二次改票卡在原中继，又签了第三次 | 把第三次交给其他中继即可，不必先发布第二次；第二次日后上链也不会覆盖第三次 |
| 点提交后刷新页面，又发了一遍 | 重发同一原票不会双计，也不会自动生成新票 |
| 新票待发布，旧票已收录 | 仍显示旧票为当前有效选择，并突出待发布修改 |
| 只在截止后才发现冲突 | 不能补签改变已截止结果；该地址按既定冲突规则处理 |

撤回动作也需要及时公开。下载文件、从本地清单删除地址或清浏览器缓存，都不会撤回已经上链的票。

## 7. 故障和其他争议

**官方中继停机或迟迟未发布。** 下载已签 envelope，切换另一个中继，或交给帮助者代发。同一原票不需要重新签名；帮助者只能发布，不能改选择。帮助者可用自己的普通 CKB 支付费用，不要求小林的存款地址有零钱。所有免费中继与帮助者均不可用时，页面显示待发布/服务不可用，不能要求用户付费或充值；仍可能错过截止，因此备用赞助预算和恢复演练是上线门槛。

**截止前已签，截止后才上链。** 显示迟到、不计入。中继回执可以作为失职证据，不能让管理员补写一个更早时间。

**原论坛帖子被修改。** 显示冻结版与当前版差异。对实质变动公开标记争议，必要时按治理程序重开；当前票不会被搬到修改后的提案里。

**两个节点或验证器给出不同结果。** 结果页显示数据不足或争议，公开差异，暂停确定结论和未执行付款。不能挑有利的一份，也不能取昨日缓存当正常结果。

**发生链重组。** 孤块里的票退回待收录或失效状态，余额与截止位置按原规则重算。页面展示影响，按预定确认和复核政策处理；不承诺 PoW 绝对不可逆。

**有人投诉漏票或重复计权。** 以 poll_id、ballot_id、链上位置、outpoint 和规则版本提交复核材料。复核可以补齐漏读的公开历史，不能在复核期新增选票或改变门槛。

## 8. 截止后怎样走到拨款

1. 到达固定链时钟边界后停止接受能计入本轮的新出现，进入等待确认状态；已经签好但尚未及时上链的不计。
2. 按历史收录时授权核对各地址的候选票，应用直接优先、锚点排序、撤回屏障和冲突规则，计算截止本金并生成 result_core 与完整证据包。
3. 两套独立实现重建历史并比较结果；任何人可下载原票、逐 cell 明细和复算指令。数据不完整时不发布正常通过结论。
4. 在预先确定的复核窗口处理计算、取数和规则适用争议。页面分别展示计算结果、验证状态和治理处置状态。
5. 委员会按现有多签流程人工付款，并可在提案页附付款交易链接。投票网站没有金库密钥，不会因后台出现 `passed=true` 自动发钱。

确认深度和复核窗口目前仍是设计候选，正式使用前固定并公布；不能把“几个确认”描述成每次必定只需某个分钟数。
