# 外部验收记录模板：真机、真人、独立实现与运营

[14 §8](14-implementation-status.md) 列出的门槛只能由真人、真设备、另一位作者或独立运营者完成。本文给出操作步骤与记录格式，**没有填写任何通过结论**。

以下都不能代替这些门槛：
- 开发链；
- 公开测试密钥；
- 浏览器自动化（`deploy/devnet/run-e2e.sh`，桌面与手机尺寸 Chromium，以及加载开发版签名插件的 Chromium）；
- 模拟钱包；
- 本机上的两个服务。

它们只证明软件闭环。真实验收之前，可先复跑这些脚本，确认软件本身没有退化。

## 1. 每次演练的固定输入

先记录：

- 源码 commit、发布包 SHA-256、包内 `BUILD.txt`；
- 网络名与 genesis hash、节点 tip 的高度与哈希；
- `GET /api/network` 中的 roles、rules、policy、registry 哈希与流程期限；
- 中继 URL 与回执公钥（`/api/status` 的 `relay.receipt_key`）、独立来源 URL（[15 §7.1](15-operations.md)）。

**演练对象与密钥**：
- 演练使用明确无治理效力的测试网提案，服务处于影子模式；
- 记录全部发起人与投票 owner 的完整 lock；
- 不保存助记词、私钥或未脱敏的设备身份；
- 测试密钥不能持有主网资产。

**参与者信息**：记录代号、日期、设备、操作系统、钱包、App 与固件版本、连接方式。

**每个用例保存**：
- 签名的完整 UTF-8 文本；
- 对象 ID 与信封哈希、回执；
- 链上收录位置；
- 收录后 `GET /api/owners/{owner_id}/ballots` 显示的当前选择；
- 页面截图；用硬件钱包时还要设备屏幕照片。

**隐私告知**：签名可以公开验证，GRANT 会公开“哪个密钥代表哪些存款”，参与者需事先知道这一点。

## 2. 钱包与 owner

记录工具是前端的「钱包检查」页（`#/wallet-check`）：它生成固定样票，验证签名并下载记录。需要对照时，可用 `omavote sign --format ckb|evm` 生成参考签名。

| 用例 | 操作 | 必须记录的证据与判断 |
|---|---|---|
| Neuron 软件钱包 | 添加完整 owner 地址；复制全文签 GRANT 并导入签名；发起人签提案；owner 直接投 YES、NO、CANCEL 各一次 | 地址对应完整 lock；65 字节消息签名在本地验证通过；没有要求签交易或移动本金；签名文本与导出的对象哈希一致 |
| Neuron + Ledger | 同上，另测中英文、长标题、三种选择和换钥 | 固件、App 与 Neuron 版本；设备首行实际显示的动作、短提案 ID 或目标密钥、到期日（[11 §4.1](11-authorization.md)）。网页截图不能代替设备显示 |
| MetaMask 桌面版 | 单独的投票账户；连接、签代理票、断开与重连、切换账户 | 弹窗能核对全文、owner、预算、收款人和选择；切换账户后未完成的草稿被清除；没有出现转账请求 |
| MetaMask 手机版 | 在 App 内浏览器完成授权、YES→NO→CANCEL、换服务器后重连。前端未接 WalletConnect | 钱包版本、操作与连接次数、签名弹窗全文的录屏。手机尺寸的自动化测试不能代替 |
| Omavote 签名插件 | Chrome、Brave、Edge、Arc 各一次：安装（记录安装提示的权限文字）；创建 key；官方域名上一键连接；自托管站点从工具栏连接并在 Chrome 权限框同意；Neuron 授权插件 key；一次确认为多个 owner 签票；锁定、自动锁定与解锁；重启浏览器后仍为锁定；断开站点；重置 key 并以 GRANT+CANCEL 换 key（[19](19-signer-extension.md)） | 浏览器与插件版本；安装提示只列官方域名；确认窗口完整显示来源、key 地址、提案编号、选择和全部 owner 地址；GRANT 首行地址缩写与插件显示一致；断开后旧确认窗口不能签名；没有出现转账或交易请求 |
| 多地址与多笔存款 | 1、3、10 个 owner，其中至少一个有多笔 DAO 存款；分别添加、授权、签票 | 每个地址的本金与笔数、发现方式；遗漏的 owner 与本金单独列出 |
| EVM owner lock | Omnilock（auth flag 0x01、0x12）与 PW Lock 的普通模式，使用真实存款的完整 script | 实际 args 与 flags 和网络注册表一致；多签、passkey 等不支持的模式被明确拒绝，不被当作普通 EOA |

以下场景必须分别演练，并逐个 owner 记录：
- 授权流：安全换钥（GRANT 带 `STOP_AND_CANCEL_OPEN`）、自然到期、REVOKE `STOP_ONLY`、REVOKE `STOP_AND_CANCEL_OPEN`、同锚点冲突、owner 接管后继续改票；
- 不同 owner 的到期时间、部分恢复与中断恢复。

预期结果（[11 §6–8](11-authorization.md)）：

| 动作 | 结果 |
|---|---|
| 自然到期、STOP_ONLY | 保留此前的有效票 |
| 安全撤回 | 撤回未结束的旧代理票，不会回退到更早的代理票 |
| owner 直接投票之后 | 新的代理票不能覆盖 owner 的直接票 |

## 3. 免费路径与故障切换

1. **零余额**：owner 只持有 DAO 存款，owner 与投票密钥的普通余额都为零（`omavote devnet balance` 只用于开发链；测试网用节点的 `get_cells_capacity`）。各种选择和撤回都应免费发布。记录赞助者的资金 lock 与网络费。不要给用户充值来规避这个条件。
2. **停掉主中继**：主中继收到签名消息后，停止它的 API 与发布者。保存原信封和回执。
3. **备用中继准备**：另一家运营者用自己的已验证节点、数据库、回执密钥和赞助账户提供免费出口。
4. **切换后重发**：
   1. 在「设置」中改用备用中继，核对网络与新的回执公钥；
   2. 在「回执」页原样重发。

   对象 ID 必须相同，不需要重签。若锚点已被孤立，页面要明确提示重签。
5. **记录各阶段时间**：签完、`RECEIVED`、`BROADCAST`、`INCLUDED`、成为当前选择、最终计入。截止前未收录的消息不算成功；故障时不承诺一定赶上截止。
6. **主中继恢复**：主中继恢复后，同一信封显示为 `ALREADY_ON_CHAIN`，结果相同。两家运营者各自用 `?history=true` 保存证据包，并运行 `omavote verify-evidence --rpc`。

邀请 8–12 位不同背景的参与者覆盖上述设备，按 [05 §7](05-delivery.md) 记录每人的：
- 操作时间与链上等待；
- 签名与弹窗次数；
- 失败原因与遗漏的本金。

未达目标时如实记录。建议每人每个 owner 一行：参与者、钱包版本、owner_id、本金、动作、旧/新 key ID、授权到期、锚点、对象 ID、各阶段时间、最终权重、失败原因、证据路径。空白表示未测，不等于通过。

## 4. 独立实现与安全审查

**审查方式**：
- 由另一位作者或团队，依据 [03](03-protocol.md)、[11](11-authorization.md)、[13 §4](13-technical-plan.md)、`schemas/` 与 `vectors/` 审查或重新实现；
- 先审查公开输入，再看参考结果，避免照抄参考算法；
- 用自己的节点取得完整历史。

**覆盖范围**：编码与用途域、适配器验签、授权控制与屏障、同锚点冲突、乱序收录、截止快照、DAO phase-1、载体与 witness 限制、证据包完整性、重组。

**对真实提案运行的检查**：
- `omavote verify --check-clock`（从创世块）；
- `omavote verify --from-height H0 --compare`；
- `omavote verify-evidence --rpc`；
- `scripts/diff-verifiers.sh`；
- 审查者自己的实现。

**比较与记录**：
- 先比较完整的 `result_core`，再比较 `result_hash`；
- 记录审查者的身份、组织，以及是否运营中继。

**当前状态**：仓库里的两套实现出自同一模型（[14 §6](14-implementation-status.md)），多跑几次也消除不了这一点。出现分歧时，保留输入、版本与最小反例，暂停执行再排查。

## 5. 真实规模与运营

**规模实测**：
- 用自有的主网或测试网全节点固定 genesis 与 tip，统计 DAO 存款的完整 lock 分布、本金，以及支持与不支持的模式。
- 分别测量以下场景：
  - 从创世块的完整回放；
  - H0 的种子推导与 `--compare` 比对；
  - 冷启动；
  - `rebuild-index`；
  - 并发查询。
- 每个场景记录：区块、交易与 cell 数，耗时，CPU，峰值内存，数据库与节点磁盘，索引落后量。
- 注明机器配置、节点版本、缓存冷热和测量区间。测量途中发生重组或 RPC 数据不完整时，要重测。

**运营记录**：
- 公网域名与 TLS；
- 实际部署的二进制与前端版本；
- 独立来源的 CORS；
- 赞助的网络费与可回收容量；
- 两家运营者的值守安排、截止前的积压；
- 备份与恢复演练（`omavote backup`、`rebuild-index`，[15 §9](15-operations.md)）；
- 故障切换演练（§3）。

长期观测的区间由运营者确认，本地几分钟的测试不能代替。在未经验证的公网环境里，不要设置 `governance_confirmed = true`。

| Neuron、Ledger 与 MetaMask 桌面及手机的真机签名 | 未完成 | 待真机记录（§2） |
| 8–12 人体验、1/3/10 个 owner、免费路径与独立出口 | 未完成 | 待参与者计时与运营者报告（§3） |
| 另一作者的验证器与独立安全审查 | 未完成 | 待审查者的完整结果比较（§4） |
| 主网或测试网的真实规模与长期运行 | 未完成 | 待自有节点与部署实测（§5） |
| 影子运行差异解释与治理批准 | 未完成 | 按 [18](18-governance-switch-proposal.md) 走既有流程 |

这些结论不由自动测试、开发者提交或本模板产生。原始证据与未解决的问题一并公开，写明验收范围后，再更新 [14](14-implementation-status.md) 的状态。
