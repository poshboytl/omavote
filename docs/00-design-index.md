## 建议先读的结论

采用 **B：存款钱包或已授权 key 签署限定本提案的选票，开放中继代付把完整选票与签名发布到 CKB，任何人按固定规则独立复算**。继续使用 Nervos DAO 本金线性票权，讨论留在 Nervos Talk，金库沿用现有执行流程。

用户免费是产品硬约束：中继/运营方承担交易费和载体周转容量，授权、续期、投票、改票、撤销和恢复不向用户收费。中继不能伪造选民授权或成为唯一提交入口。用户不迁移存款，不把 DAO 本金交给新合约。链上公开数据让已及时发布的有效票可重建，但不消除矿工审查、链重组、恶意前端或真实资本控制大量票权的问题。

默认支持经真实验证的标准单签和常见 EVM 控制的 CKB locks；Neuron、PW、JoyID、硬件钱包的范围按脚本与实际交互决定，不能用钱包名称代替授权验证。核心钱包消息签名不可行时，只有通过免费赞助与逐 lock 安全验收的 C 交易通道才可加入支持范围；不以强制迁移老存款解决兼容性。

首版支持一次授权、多次投票，界面默认一年（365 链日），用户可选 30 天或 90 天，不提供永久授权。Neuron 用户首次用每个存款地址授权第二个在线钱包，同地址多笔 deposit 无须逐笔操作；之后连接同一在线钱包，为各 owner 签署具体提案的票，不必每次打开 Neuron。界面可以合并操作，钱包弹窗次数按 adapter 实测公布。本机密钥为可选候选；直接票与 owner 恢复始终保留。

默认普通 carrier，无新 type script、无自动延期和任意规则引擎。完整规则、授权与选票公开；按各 owner 核对历史权限再排序；自然到期与安全撤销分开；数学计票与治理处置分开。浏览器验证须说明范围，第二独立 verifier 保留。

## 与用户约束逐项对应

| 约束 | 本设计落实 |
|---|---|
| 计算方式应保持不变 | 保留 Nervos DAO 本金线性权重与现有门槛；不加入利息、时长、平方根或投票代币；未定义边界先澄清 |
| 钱包支持可以讨论 | 发布完整 lock 模式与钱包版本矩阵，先验证核心路径，再决定首版覆盖 |
| 用户投票必须免费（最新确认） | 中继/运营方承担链费和周转容量；故障时使用备用中继或帮助者代付，不把用户付费作为正常或应急完成条件 |
| 有后台时结果可验证 | 原始签名、链上位置、票权明细、固定规则、完整证据包、独立 verifier |
| 降低后台依赖不能造成巨大体验退步 | 正常路径只需签消息；中继自动发布；把多地址 Neuron 和故障切换纳入实测门槛 |
| 关注 token 安全与作弊 | 默认投票不消费 DAO cell；资产主体去重；拒绝把任意交易 input 当作通用授权 |

## 最关键的研究发现

1. 旧问题不只是账号作弊。公开调查确认，同一资产地址换绑账号造成重复权重；新工具必须把唯一性落到完整 lock 和 DAO outpoint。
2. 可验证加法不等于可验证完整性。一个系统可能对收到的票算对，却漏掉其他有效票；Merkle root、分片或多个 API 都不能自动解决这个问题。
3. CKB 历史票权不能靠今天的 live cells 还原。创建交易 proof 也不证明截止时没有花费，需要完整历史、已验证 checkpoint 或覆盖充分的证明。
4. 签名或交易成功不自动等于声明的存款主体授权。必须把密码学身份和具体 lock 关联；ACP、特殊 Omnilock、多签、动态子密钥不能通用放行。
5. 轻量可以是少产品、少身份系统、少资产权限，不能省掉原始证据和独立恢复。后台关闭后仍可发布和复算应是交付验收，不是未来愿望。

上述事实与源码链接分别见研究依据；本设计没有把论坛意见视为已通过规则，也没有声称完成现有产品的全面安全审计。

## 需要明确但不能代替社区宣布的边界

推荐统一按截止状态结算 active deposit 原始 capacity；这是对“当前持有”的候选解释，并非断言与历史 Metaforo 逐票完全相同。资料对逐次查询与最终快照、小数截断层级、phase-1 提款、67% 包含边界及七天的链时间映射存在歧义。

正式切换前，应把它们写成可比较的规则 profile，取得相应确认，再用于有治理效力的投票。发布方式与票权政策是独立的选择：采用 B 不强制采用新的快照政策。研究模型使用“截止状态 + 精确 shannon”以检查安全性质，不能被当成该政策已获授权。

## 已验证与未完成

初次研究核验运行 **39 项模型测试，全部通过**，其中一项对 **1,000 份固定种子随机历史** 检查本金守恒、重复广播幂等和读取顺序无关。本轮未修改模型逻辑；这些既有结果不覆盖 V2 可读票面、期限型授权、控制冲突、安全撤回屏障、真实签名或密钥保管。模型不联网、不操作钱包、不广播交易；它假定输入历史完整、授权已验证。

这不是密码学测试、CKB-VM 验证、钱包真机验收、完整节点压测或正式审计。上线仍要完成这些项目，以及第二套独立 verifier、实际断站恢复演练和影子投票。原两人 8–12 周是加入完整授权前的粗估，当前范围必须在 P0 重新估算，不能据此承诺上线时间。

调研收集了 28 个主题的 637 条帖子用于检索和定向深入阅读，不表示逐条审计；仓库 HEAD 快照也不证明线上实际部署版本相同。
