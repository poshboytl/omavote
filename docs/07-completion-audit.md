## 2. 核心不变量逐项检查

| 协议不变量 | 核验范围与证据 |
|---|---|
| 同一本金最多计一次 | owner/outpoint 模型；重复广播、多个 deposit、提款再存及随机守恒测试 |
| 只有合法授权主体可改票 | 协议规定完整 lock adapter、域分离、历史授权；ACP/多签等失败模式已分析。真实验签仍属未来实现门槛 |
| 提案内容、金额、接收方、规则不可暗改 | Manifest/poll/rules hash 的字段和变更重开规则已定义；未声称已实现生产编码器 |
| 同一规范历史给出相同结果 | 模型先按规范位置处理，乱序读取和重复广播测试通过；真实链完整性为模型前提 |
| 数据不足不得变为零余额 | 协议定义 DATA_INCOMPLETE；模型缺失标记测试通过。模型不会自行发现上游偷偷漏块 |
| 默认投票不消费 DAO 本金 | 架构是限定消息加中继自有资金；交易通道另设资产选择约束。没有广播真实交易来验证此项 |

六项均已在初步设计中给出明确机制、前提或上线验收；其中尚未实现的密码学、链验证与钱包部分没有被模型测试覆盖声明取代。

## 4. 尚未发生的下一阶段工作

以下是设计明确要求的未来门槛，不是本次已完成事项：

* **规则确认**：快照时点、提款第一阶段、精度、67% 边界、时钟与 proposer 检查时点，由既有治理流程确认；技术设计不代替批准。
* **P1 技术 PoC**：真实钱包签名、主体关联、carrier 回收后查证、历史状态和重组实验。
* **产品实现**：静态前端、服务、中继、钱包 adapters、完整 CLI 和确定性编码器。
* **安全与体验验收**：真实 CKB-VM 攻击 fixture、独立第二 verifier、真机与用户测试、完整节点性能、断站恢复演练。
* **上线与迁移**：影子投票、差异解释、发布许可选择、正式切换授权、运维及数据镜像。

这些门槛均有对应的候选选择或验收条件。用户要求的是初步设计及深入权衡，没有要求本次同时部署产品、替 DAO 决定规则、操作钱包或上线金库自动执行。
